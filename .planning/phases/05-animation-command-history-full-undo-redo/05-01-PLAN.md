<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI Actions -> CommandHistory | Continuous user pointer events and numeric inputs produce delta commands pushed to the history stack. |
| Command History -> Animation Data Model | Commands execute and unexecute directly on in-memory Clip, Track, and Keyframe data structures. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | CommandHistory.cs (Track Sorting) | high | mitigate | All commands modifying keyframe timestamps (AddKeyframe, MoveKeyframes, DeleteKeyframes) call track.SortKeys() in both Execute() and Unexecute() to prevent chronological ordering corruption. |
| T-05-02 | Denial of Service | CommandHistory.cs (Memory Limits) | medium | mitigate | CommandHistory enforces maxHistoryDepth (100 entries) with stack trimming; delta commands store only scalar values and object references rather than document snapshots. |
| T-05-03 | Tampering | CommandHistory.cs (Duplicate Keyframe Overwriting) | high | mitigate | AddKeyframeCommand captures any existing keyframe at the target timestamp in _replacedKeyframe and restores it on Unexecute(), preventing permanent data loss. |
| T-05-04 | Repudiation | CommandHistory.cs (Composite Atomicity) | medium | mitigate | Multi-keyframe/multi-track changes are wrapped in CompositeCommand, executing forward and unexecuting in strict reverse order (per D-04) to avoid partial state restoration. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero external packages; pure BCL and internal C# 5.0 types only. |
</threat_model>
